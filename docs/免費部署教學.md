# 免費部署教學（給非工程師）

完成後你會得到一個網址（例如 `https://school-zone.onrender.com`），在任何電腦或手機的瀏覽器都能開啟。**全程免費，不需要信用卡**，也不需要在自己的電腦安裝任何軟體。

## 會用到的免費服務

| 服務 | 用途 | 你需要做的 |
| --- | --- | --- |
| GitHub | 存放程式碼、每天早上自動寄提醒信 | 你已經有帳號 |
| Neon（neon.tech） | 資料庫，存放案件、待辦、公文 | 註冊 |
| Render（render.com） | 讓網站上線 | 註冊 |
| Gmail | 寄出每日提醒信（可最後再做） | 建立「應用程式密碼」 |

整個流程分 5 個階段，請**一次做一個階段**。每個階段最後都有「怎麼確認成功」。

> 準備一個「記事本」（Windows 的記事本或 Mac 的備忘錄），把過程中要記下來的東西貼在裡面。**這份記事本裡會有密碼，請不要傳給別人，也不要貼到聊天對話中。**

## 階段 1：建立免費資料庫（Neon）約 5 分鐘

1. 打開瀏覽器，前往 **https://neon.tech**
2. 點右上角 **Sign up**（註冊）。
3. 選 **Continue with GitHub**（用 GitHub 登入），依畫面按「Authorize（授權）」。
4. 進入後會出現建立專案的畫面（Create project），填寫：
   - **Project name**：輸入 `school-zone`
   - **Postgres version**：不用改
   - **Region（地區）**：選 **AWS Asia Pacific (Singapore)**（離台灣最近）
5. 按 **Create project**。
6. 建立完成後，找到 **Connect**（連線）按鈕並點它，會跳出一個視窗：
   - 找到 **Connection pooling** 開關，**把它關掉**（關掉後網址裡不會有 `-pooler` 字樣）
   - 視窗中有一串很長、以 `postgresql://` 開頭的文字，點旁邊的 **複製** 圖示
7. 貼到你的記事本，標註「資料庫網址」。它長得像這樣：
   ```
   postgresql://neondb_owner:xxxxxxxx@ep-xxxx-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```

> 如果這串文字最後有 `&channel_binding=require`，請把這一段刪掉，只保留到 `sslmode=require` 為止。

**怎麼確認成功：** 記事本裡有一串 `postgresql://` 開頭、`sslmode=require` 結尾的文字。

## 階段 2：讓網站上線（Render）約 15 分鐘

### 2-1 註冊

1. 前往 **https://render.com**，點 **Get Started for Free**。
2. 選 **GitHub** 登入，按「Authorize」授權。
3. 如果要求填寫名字、用途，隨意填寫即可。

### 2-2 建立網站

1. 在 Render 首頁點右上角 **+ New**，選 **Web Service**。
2. 「Source Code」選 **GitHub**。如果看不到你的儲存庫 `116-`：
   - 點 **Configure GitHub** 或 **Connect GitHub**
   - 在 GitHub 頁面選「Only select repositories」→ 勾選 `116-` → 按 **Install** 或 **Save**
3. 回到 Render，在清單中點選 **wandalin0057/116-**。
4. 接下來是設定畫面，依序填寫：

   | 欄位 | 填寫內容 |
   | --- | --- |
   | Name | `school-zone`（這會變成網址的一部分；若被用走，改成 `school-zone-你的英文名`） |
   | Language | 應會自動顯示 **Docker**，不用改 |
   | Branch | `claude/school-zone-project-management-py4y8z` |
   | Region | **Singapore** |
   | Instance Type | 點選 **Free**（$0） |

5. 記下網站網址：`https://` + Name + `.onrender.com`，例如 `https://school-zone.onrender.com`，寫到記事本「網站網址」。

### 2-3 填寫環境變數（網站的設定值）

往下找到 **Environment Variables**，點 **Add Environment Variable**，一列一列加入下表。左邊填在「NAME_OF_VARIABLE」格，右邊填在「value」格。

| 名稱（左格，請一字不差） | 值（右格） |
| --- | --- |
| `DATABASE_URL` | 階段 1 記下的資料庫網址 |
| `APP_URL` | 你的網站網址，例如 `https://school-zone.onrender.com` |
| `SESSION_SECRET` | 點 **Generate**（產生）讓系統自動填入 |
| `DATA_ENCRYPTION_KEY` | 點 **Generate** |
| `CRON_SECRET` | 點 **Generate** |
| `COMPANY_NAME` | 你的公司全名，例如 `○○交通工程顧問有限公司` |
| `INITIAL_ADMIN_EMAIL` | 你自己的 Email（之後用來登入） |
| `INITIAL_ADMIN_PASSWORD` | 自訂一組密碼：**至少 10 個字，要有英文字母和數字**，例如 `School2026abc`（請自己另想一組） |
| `INITIAL_ADMIN_NAME` | 你的姓名 |
| `EMAIL_PROVIDER` | `console` |

> 如果畫面上沒有 **Generate** 按鈕：請自己隨意打一串 40 個以上的英文與數字混合（例如亂按鍵盤），三個欄位各打不同的一串即可。
>
> **重要：`DATA_ENCRYPTION_KEY` 填好之後永遠不要修改**，否則系統裡已儲存的「下載密碼」會無法讀取。

### 2-4 健康檢查並部署

1. 往下找到 **Advanced**（進階）並展開。
2. **Health Check Path** 填：`/api/health`
3. 按最下方 **Deploy Web Service**。
4. 畫面會出現一直跑動的文字（建置紀錄），**第一次大約需要 10～15 分鐘**，請耐心等候。
5. 看到綠色的 **Live** 或「Your service is live 🎉」就完成了。

**怎麼確認成功：**
1. 在瀏覽器打開「網站網址」，應該看到「通學區案件期程暨發文管理系統」登入畫面。
2. 再打開「網站網址」後面加上 `/api/health`（例如 `https://school-zone.onrender.com/api/health`），應該看到 `"status":"ok"`。

> 如果紀錄最後出現紅色 **Failed** 或 **Deploy failed**：把紀錄最後 30 行左右複製給我（**先確認裡面沒有密碼**），我幫你看。

## 階段 3：第一次登入與基本設定 約 10 分鐘

1. 打開網站網址，用階段 2 填的 `INITIAL_ADMIN_EMAIL` 和 `INITIAL_ADMIN_PASSWORD` 登入。
2. **立刻改密碼：** 左側「系統設定」→「個人帳號」→ 輸入目前密碼與新密碼 →「變更密碼」。
3. **刪除初始密碼設定：** 回到 Render → 點你的網站 → 左側 **Environment** → 找到 `INITIAL_ADMIN_PASSWORD` 那一列 → 點垃圾桶圖示刪除 → **Save Changes**（網站會自動重新啟動，約 3～5 分鐘）。
4. **新增同事帳號：** 「系統設定」→「使用者管理」→「新增使用者」。
5. **核對假日資料：**
   - 前往 https://data.gov.tw/dataset/14718 ，下載「115年」的 CSV 檔
   - 網站「系統設定」→「工作天設定」→「匯入官方辦公日曆」→ 選擇檔案 →「解析並預覽差異」→ 填寫原因（例如「核對官方日曆」）→「確認匯入」
6. **試用：** 「學校案件」→「新增案件」，填入一所學校與機關通知日，儲存後看「期程工作」是否自動出現期限。

**怎麼確認成功：** 你能用新密碼登入，並看到剛新增學校的期程工作清單。

## 階段 4：設定 Gmail 寄信（每日提醒用）約 10 分鐘

> 這個階段可以晚一點再做。不做的話網站照常可用，只是不會寄每日提醒信。
>
> 為什麼不在 Render 寄信？Render 免費方案自 2025 年 9 月起封鎖對外寄信，所以改由 GitHub 每天早上 8 點自動寄出。

### 4-1 建立 Gmail 應用程式密碼

建議用一個專門寄通知的 Gmail 帳號（也可以用你自己的）。

1. 用該 Gmail 帳號登入，前往 **https://myaccount.google.com/security**
2. 找到「**兩步驟驗證**」，如果是關閉的，請依畫面開啟（需要手機）。
3. 開啟後，前往 **https://myaccount.google.com/apppasswords**
4. 「應用程式名稱」輸入 `school-zone`，按「建立」。
5. 畫面會顯示一組 **16 個英文字母**的密碼（例如 `abcd efgh ijkl mnop`）。
6. 抄到記事本「Gmail 應用程式密碼」，**去掉中間的空格**，變成 `abcdefghijklmnop`。這組密碼只會顯示一次。

### 4-2 把設定存到 GitHub

1. 打開 **https://github.com/wandalin0057/116-**
2. 點上方 **Settings**（齒輪圖示）。
3. 左側選單找到 **Secrets and variables** → 點 **Actions**。
4. 點綠色按鈕 **New repository secret**，一次新增一個，共 5 個：

   | Name（請一字不差） | Secret（值） |
   | --- | --- |
   | `DATABASE_URL` | 階段 1 的資料庫網址 |
   | `SITE_URL` | 網站網址 |
   | `GMAIL_ADDRESS` | 寄信用的 Gmail 地址 |
   | `GMAIL_APP_PASSWORD` | 4-1 的 16 碼應用程式密碼（無空格） |
   | `TEST_RECIPIENT` | 你自己的 Email（測試信寄到這裡） |

   每個都要按 **Add secret** 儲存。

### 4-3 設定網站的測試收件人

網站「系統設定」→「通知設定」→ 右邊「Email 寄送設定」：
- 勾選「測試模式」
- 「測試收件人」填你自己的 Email
- 按「儲存 Email 設定」

（網站上的「寄送測試信」按鈕在免費方案無法使用，請用下一步測試。）

## 階段 5：測試每日提醒 約 5 分鐘

1. 先確認網站裡有至少一件「今天或未來 3 個工作天內到期」或「已逾期」的工作（可在「工作待辦」查看）。
2. 打開 **https://github.com/wandalin0057/116-** ，點上方 **Actions**。
   - 若看到「Workflows aren't being run on this repository」或類似提示，按綠色按鈕 **I understand my workflows, go ahead and enable them**。
3. 左側點 **每日提醒**。
4. 右邊點 **Run workflow** → 勾選「非工作天也執行（測試用）」→ 按綠色 **Run workflow**。
5. 等約 2～3 分鐘，重新整理頁面，出現**綠色勾勾**表示成功（紅色叉叉請點進去把錯誤訊息給我看，記得先確認裡面沒有密碼）。
6. 到「測試收件人」信箱收信，主旨會是「［測試］【通學區案件】……每日工作提醒」。也請看一下垃圾郵件匣。
7. 在網站「提醒紀錄」可以看到這次寄送紀錄。

**正式啟用：** 確認信件內容正確後，網站「系統設定」→「通知設定」→ **取消勾選「測試模式」** → 儲存。之後每個工作天早上 8 點左右，每位同事會收到自己的提醒信。

## 免費方案的限制（請先了解）

| 限制 | 影響與建議 |
| --- | --- |
| 網站閒置 15 分鐘會「休眠」 | 第一個人打開時要等約 1 分鐘才出現畫面，之後就正常速度 |
| Render 免費主機速度較慢 | 登入、匯出 PDF 可能要等幾秒 |
| Neon 免費資料庫容量 0.5 GB | 以文字資料為主，數百所學校也用不完 |
| GitHub 排程可能延遲 | 排程訂在 9:05，提醒信約在 9:05～9:30 之間寄出 |
| 儲存庫若 60 天沒有任何更新，GitHub 可能自動暫停排程 | 到 Actions →「每日提醒」若看到停用提示，按 **Enable workflow** 即可 |
| Gmail 每天寄信上限約 500 封 | 一般使用量遠低於此 |
| 免費方案沒有自動備份保證 | **建議每週一次**：網站「系統設定」→「資料備份」→「下載備份檔」，存到公司電腦 |

日後若要正式長期使用、追求穩定，可再考慮升級 Render 付費方案（不休眠、可直接寄信）。

## 常見問題

**Q：打開網址一直轉圈圈？**
網站正在從休眠中醒來，請等 1 分鐘再重新整理。

**Q：忘記管理員密碼？**
如果還有其他管理員，請他到「使用者管理」幫你重設。若只有你一位管理員：到 Render → Environment，把 `INITIAL_ADMIN_EMAIL` 改成一個**新的** Email、`INITIAL_ADMIN_PASSWORD` 填新密碼並儲存；網站重新啟動後用新帳號登入，再到「使用者管理」重設原帳號密碼，最後刪除 `INITIAL_ADMIN_PASSWORD`。

**Q：程式更新後要做什麼？**
Render 會在 GitHub 有新程式碼時自動重新部署，不需要操作。
